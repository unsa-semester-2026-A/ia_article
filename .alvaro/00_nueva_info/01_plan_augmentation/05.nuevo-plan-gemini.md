# Plan de Investigación: Detección Vehicular OBB con Limpieza y Aumentación Generativa (SMART Challenge 2026)

## 1. Problema de Investigación

Bajo el contexto peruano el tráfico es un gran problema a solucionar.
Una de las mejoras para ayudar con su estudio es la detección de vehículos
mayoritariamente peruanos y en la zona de Perú, pero no hay muchos datasets disponibles

La capacidad de los modelos de `deep learning` muchas veces se ve limitada por
la cantidad de datos existentes. Así que se usará un dataset reciente y técnicas
de `data augmentation` para poder incrementar la potencia de los modelos de
machine learning.

Se usará el dataset del reto SMART Challenge (del MTC), pero presenta etiquetas
de autos solo en movimiento (ya que ese es el objetivo de la competencia), es
por eso que omite los estacionados. Y tiene otras limitaciones que degradan el entrenamiento.

Esto fuerza a los detectores a memorizar el fondo en lugar de la semántica del
vehículo. Las estrategias clásicas de ignorar o descartar datos fallan debido a
la alta correlación espacial del ruido en cámaras de tráfico fijas.

---

## 2. Metodología y Pipeline de Ejecución

El núcleo de la investigación es eliminar la ambigüedad desde la raíz utilizando
modelos de pesos abiertos para limpiar los datos y, posteriormente, enriquecer
las clases minoritarias.

### Fase 0: Autolabeling con YOLO y Filtro de Movimiento

* **Objetivo:** Encontrar los vehículos estacionados que el dataset original no etiquetó.
* **Mecanismo:** 1. Se entrena un modelo ligero de última generación (**YOLO26-nano**). Al existir ya YOLO26, es preferible usar su variante ligera en lugar de arquitecturas previas (como YOLOv11) para mantener consistencia algorítmica en todo el estudio y aprovechar su inferencia optimizada para OBB. Se entrena **solo** con los vehículos en movimiento ya anotados para que aprenda la apariencia visual desde la vista de dron.

2. Se corre este YOLO26-nano sobre todo el dataset para realizar *pseudo-labeling*, detectando absolutamente todos los vehículos (en movimiento y estacionados).
3. Se cruzan estas detecciones con las etiquetas originales (Ground Truth). Aprovechando la estructura temporal del dataset (organizado en clips continuos de ~50 frames), las detecciones de YOLO que *no* tienen un Ground Truth asociado y cuyo centroide se mantiene estático entre frames vecinos, se marcan definitivamente como "vehículos estacionados que deben ser borrados".

### Fase 1: Corrección por Inpainting (Limpieza)

* **Modelo:** **LaMa** (Large Mask Inpainting).
* **Acción:** LaMa toma las máscaras generadas en la Fase 0 y reconstruye el fondo (asfalto, líneas) sobre los vehículos estacionados. La imagen de entrenamiento queda libre de ambigüedades, evitando penalizar al modelo final cuando detecta correctamente un vehículo.

### Fase 2: Aumentación Generativa (Opcional/Extensión)

* **Acción:** El dataset presenta un desbalance extremo (los autos comunes representan el ~80%, mientras que clases como el Microbús o el Ómnibus Articulado rondan el 0.47% y 0.04% respectivamente). Para solucionarlo, se usarán **scripts en Python** de programación clásica para generar procedimentalmente mapas/disposiciones de calles aleatorias (vías rectas, curvas, intersecciones).
Estos mapas simples servirán de guía geométrica para que **ControlNet/LDM** genere fondos viales realistas y vacíos. Finalmente, se aplicará composición sensible a la escala (Poisson Blending) para inyectar recortes de las clases minoritarias peruanas (combis, mototaxis) en estas calles sintéticas.

## 3. Diseño Experimental (Estudio de Ablación)

Para medir exactamente de dónde proviene la mejora del rendimiento y aislar el impacto de cada fase de nuestro pipeline, se evaluará la misma arquitectura objetivo (**YOLO26-OBB**) bajo cinco condiciones incrementales:

| Condición | Estrategia de Datos | Propósito Científico |
| --- | --- | --- |
| **Base 0 (Zero-Shot)** | Sin entrenamiento. Usar YOLO26-OBB con sus pesos pre-entrenados (COCO/DOTAv2). | Demuestra empíricamente que los modelos *off-the-shelf* fallan en el contexto peruano/nadir y necesitan ajuste. |
| **Base 1 (Data Cruda)** | Entrenamiento normal con el dataset original tal cual viene (100% data original). | Línea base real. Mide el techo de rendimiento cuando el modelo se asfixia con el ruido de etiquetas y el desbalance extremo. |
| **Mejora A (Data LaMa)** | Entrenamiento **exclusivamente** con el dataset limpiado por la Fase 1. Es el mismo volumen de datos que la Base 1, pero con los píxeles de los autos estacionados reemplazados por textura de asfalto. | Aísla y demuestra el valor puro de **limpiar** el ruido de etiquetas generativamente, resolviendo la penalización por vehículos estáticos. |
| **Mejora B (Aumentación Cruda)** | Entrenamiento con la **Data Cruda** original + **Imágenes Sintéticas** de clases minoritarias (ControlNet). No pasa por la limpieza de LaMa. | Responde a la pregunta: ¿Es útil inyectar clases raras generadas artificialmente si el dataset base sigue teniendo ruido de etiquetas y señales contradictorias? |
| **Mejora C (Pipeline Completo)** | Entrenamiento con la **Data LaMa** + **Imágenes Sintéticas** (Fase 1 + Fase 2). | Demuestra si la sinergia de ambas fases (Dataset base libre de ambigüedades + Aumentación balanceada de clases minoritarias) es el estado del arte propuesto. |

* **Métrica Oficial:** Implementación de **Macro AP-rIoU@[0.50:0.80]** sobre un set de validación estrictamente real (sin alteraciones de LaMa ni datos sintéticos).
* **Diagnóstico Visual:** Extracción de mapas de saliencia (**Grad-CAM**) para comparar la Base 1 vs. Mejora A, buscando probar que el modelo deja de mirar el asfalto (memorización) y empieza a mirar los chasis.

## 4. Secuencia de Pasos a Seguir

1. **Preparación de Datos:** Parsear el dataset original, auditar manualmente el problema de los autos estacionados, y establecer los splits de entrenamiento/validación **a nivel de clip** (asignando los 1,088 clips íntegros a un split u otro para evitar *leakage* de datos, dado que las cámaras fijas producen fondos idénticos entre frames continuos).
2. **Autolabeling:** Entrenar YOLO26-nano con datos limpios y ejecutar inferencia + cruce temporal inter-frame sobre todo el dataset para generar las máscaras de los autos estacionados "invisibles".
3. **Limpieza Generativa:** Pasar las máscaras por LaMa para borrar los autos problemáticos y guardar este nuevo dataset limpio (Data LaMa).
4. **Síntesis (Si aplica):** Programar el script de Python para crear los esqueletos de las vías. Generar los fondos vacíos con ControlNet sobre estos esqueletos, y pegar las clases raras extraídas de la data real usando Poisson Blending para crear el paquete de datos aumentados.
5. **Implementación de Métrica:** Codificar y validar el evaluador local Macro AP-rIoU@[0.50:0.80] para que la medición sea justa y alineada al reto.
6. **Entrenamientos (Ablación):** Ejecutar los entrenamientos de YOLO26-OBB en las 5 condiciones descritas en el Diseño Experimental.
7. **Evaluación y Diagnóstico:** Extraer las métricas finales, generar los mapas Grad-CAM y analizar el comportamiento del modelo frente a clases minoritarias.
8. **Exportación Edge:** Convertir el modelo ganador a formato ONNX (cuantización FP16) y medir los tiempos de inferencia/latencia.
