# Plan de Investigación: Detección Vehicular OBB con Limpieza y Aumentación Generativa (SMART Challenge 2026)

## 1. Problema de Investigación

El dataset del reto SMART Challenge presenta **señales de entrenamiento contradictorias**: etiqueta vehículos en movimiento pero omite los estacionados. Esto fuerza a los detectores a memorizar el fondo en lugar de la semántica del vehículo. Las estrategias clásicas de ignorar o descartar datos fallan debido a la alta correlación espacial del ruido en cámaras de tráfico fijas.

---

## 2. Metodología y Pipeline de Ejecución

El núcleo de la investigación es eliminar la ambigüedad desde la raíz utilizando modelos de pesos abiertos para limpiar los datos y, posteriormente, enriquecer las clases minoritarias.

### Fase 0: Autolabeling con YOLO y Filtro de Movimiento

* **Objetivo:** Encontrar los vehículos estacionados que el dataset original no etiquetó.
* **Mecanismo:** 1. Se entrena un modelo ligero (ej. YOLOv11-nano) **solo** con los vehículos en movimiento ya anotados para que aprenda la apariencia visual de los autos desde esa perspectiva.
2. Se corre este YOLO sobre todo el dataset para realizar *pseudo-labeling*, detectando absolutamente todos los vehículos (en movimiento y estacionados).
3. Se cruzan estas detecciones con las etiquetas originales (Ground Truth). Las detecciones de YOLO que *no* tienen un Ground Truth asociado (y cuyo centroide no cambia entre frames) se marcan definitivamente como "vehículos estacionados que deben ser borrados".

### Fase 1: Corrección por Inpainting (Limpieza)

* **Modelo:** **LaMa** (Large Mask Inpainting).
* **Acción:** LaMa toma las máscaras generadas en la Fase 0 y reconstruye el fondo (asfalto, líneas) sobre los vehículos estacionados. La imagen de entrenamiento queda libre de ambigüedades.

### Fase 2: Aumentación Generativa (Opcional/Extensión)

* **Acción:** Uso de ControlNet/LDM para generar nuevos fondos viales y composición sensible a la escala (Poisson Blending) para inyectar vehículos de clases minoritarias peruanas (combis, mototaxis) en las calles limpias.

---

## 3. Diseño Experimental (Estudio de Ablación)

Para medir exactamente de dónde proviene la mejora del rendimiento, se evaluará la misma arquitectura objetivo (**YOLO26-OBB**) bajo cuatro condiciones incrementales:

| Condición | Estrategia de Datos | Propósito Científico |
| --- | --- | --- |
| **Base 0 (Zero-Shot)** | Sin entrenamiento. Usar YOLO26-OBB con sus pesos pre-entrenados (COCO/DOTAv2). | Demuestra empíricamente que los modelos *off-the-shelf* fallan en el contexto peruano/nadir y necesitan ajuste. |
| **Base 1 (Data Cruda)** | Entrenamiento normal con el dataset original tal cual viene. | Línea base real. Mide el techo de rendimiento cuando el modelo se asfixia con el ruido de etiquetas. |
| **Mejora A (Data LaMa)** | Entrenamiento con el dataset limpiado por la Fase 1 (Autolabeling YOLO + LaMa). | Aísla y demuestra el valor puro de **limpiar** el ruido de etiquetas generativamente. |
| **Mejora B (Sintética)** | Entrenamiento con Data LaMa + Inyección de imágenes generadas con nuevas instancias (Fase 2). | Demuestra si el pipeline completo (Limpieza + Aumentación Generativa) es el estado del arte para resolver desbalance extremo. |

* **Métrica Oficial:** Implementación de **Macro AP-rIoU@[0.50:0.80]** sobre un set de validación estrictamente real (sin alteraciones de LaMa ni datos sintéticos).
* **Diagnóstico Visual:** Extracción de mapas de saliencia (**Grad-CAM**) para comparar la Base 1 vs. Mejora A, buscando probar que el modelo deja de mirar el asfalto (memorización) y empieza a mirar los chasis.

---

## 4. Secuencia de Pasos a Seguir

1. **Preparación de Datos:** Parsear el dataset original, establecer los splits de entrenamiento/validación por clip y auditar manualmente el problema de los autos estacionados.
2. **Autolabeling:** Entrenar el YOLO ligero con datos limpios y ejecutar inferencia sobre todo el dataset para generar las máscaras de los autos estacionados "invisibles".
3. **Limpieza Generativa:** Pasar las máscaras por LaMa para borrar los autos problemáticos y guardar este nuevo dataset limpio.
4. **Síntesis (Si aplica):** Generar los fondos vacíos con ControlNet y pegar las clases raras con Poisson Blending para crear el paquete de datos aumentados.
5. **Implementación de Métrica:** Codificar y validar el evaluador local Macro AP-rIoU@[0.50:0.80] para que la medición sea justa y alineada al reto.
6. **Entrenamientos (Ablación):** Ejecutar los entrenamientos de YOLO26-OBB en las 4 condiciones descritas en el Diseño Experimental.
7. **Evaluación y Diagnóstico:** Extraer las métricas finales, generar los mapas Grad-CAM y analizar el comportamiento del modelo frente a clases minoritarias.
8. **Exportación Edge:** Convertir el modelo ganador a formato ONNX (cuantización FP16) y medir los tiempos de inferencia/latencia.
