\subsubsection{Dataset}
\label{sec:dataset}

The dataset is the traffic-imagery release published by Peru's Ministry of Transportation and Communications (MTC)~\cite{MTC2026SmartChallenge}. The task requires both vehicle classification and oriented localization, so each predicted instance must include a category and a rotated box. The raw archives and CSV files are treated as external inputs to the preprocessing scripts and are not redistributed with this repository. Table~\ref{tab:dataset_structure} lists the files used by the workflow and distinguishes training images, held-out images, public annotations, and the submission template.

Each object annotation stores a category identifier, box center, width, height, and angle in degrees. Multiple vehicles in one frame are separated by semicolons, while frames without annotated moving vehicles use \texttt{none}. Preprocessing converts this parametric representation to YOLO-OBB corner coordinates and remaps official class identifiers 1--9 to zero-indexed training labels. The resulting training format uses one label file per image and one line per object, with the class identifier followed by eight normalized vertex coordinates.

Frame identifiers follow the pattern \texttt{v\_[clip]\_[frame]}; the last number indicates temporal order within a short clip. This naming scheme is used for splitting because adjacent frames share background, viewpoint, and illumination. A random frame-level split could place near-duplicate evidence in both training and validation. The preprocessing stage assigns complete clips to a single subset. The dataset contains nine vehicle categories. Some of them, especially combi, microbus, and minibus, can be hard to separate from elevated viewpoints because their shapes and scales are similar. The audit checks that class identifiers are valid, dimensions are positive, centers fall inside the frame, and angles follow the expected convention. Figure~\ref{fig:dataset_obb_sample} illustrates the rotated annotation format and the motivation for using OBBs in dense traffic frames.

The audit found 601,934 annotated objects in 54,262 training frames. Of those frames, 3,394 contain no annotated objects, 6,212 contain one object, and 44,656 contain at least two objects; the maximum is 53 objects in one frame. CSV identifiers were cross-checked against archive image names to confirm one-to-one correspondence. This check is necessary because both YOLO-OBB conversion and synthetic augmentation assume exact image-label pairing. Table~\ref{tab:dataset_frame_summary} summarizes the frame-level statistics.

The class distribution is highly long-tailed. Cars represent 481,731 instances, equivalent to 80.03\% of all annotations, while articulated buses appear only 250 times. This imbalance affects both optimization and interpretation because the final metric gives equal weight to each class. A detector may perform well on cars but still obtain a limited macro score if rare categories are missed. Table~\ref{tab:dataset_class_distribution} reports the per-class distribution.

The annotation policy affects how predictions should be interpreted. The labels target moving vehicles, so visible stationary vehicles may be absent from the ground truth. A model can predict a visually reasonable stationary vehicle and still receive no match during evaluation. Section~\ref{sec:material_methods} addresses this issue through train-only pseudo-labeling of static slots and a homography-compensated motion filter used before scoring.
