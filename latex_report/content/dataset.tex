\subsection{Dataset}
\label{sec:dataset}

The data come from the SMART Challenge 2026 competition on Kaggle, organized by Peru's Ministry of Transportation and Communications (MTC)~\cite{MTC2026SmartChallenge}. The task is oriented vehicle detection and classification in traffic imagery, with predictions submitted as rotated boxes. The data preparation procedure treats the competition files as external data. Raw archives and CSV files are read by preprocessing scripts, but they are not redistributed in the source repository. Each object record contains a category identifier, center coordinates, width, height, and an angle in degrees. The center coordinates and dimensions are expressed in pixels. Frames with multiple vehicles store object records separated by semicolons; frames with no annotated moving vehicle use the literal value \texttt{none}. The preprocessing script converts these parametric OBB annotations into the YOLO-OBB corner format by computing four rotated vertices and normalizing their coordinates to the image dimensions. Official class identifiers from 1 to 9 are converted to the zero-indexed class identifiers required by YOLO training.

Frame identifiers follow the pattern \texttt{v\_[clip]\_[frame]}, where the final numeric component is the temporal index inside a short clip. This temporal structure is central to the split design. Parsing the identifiers produced 1,088 training clips and 473 test clips, with most clips containing 50 frames. Because adjacent frames within a clip share nearly the same camera viewpoint, background, and illumination, random frame-level splitting would leak near-duplicate visual evidence between training and validation. The preprocessing pipeline therefore creates a deterministic clip-level split: a whole clip is assigned either to train or validation, never to both. The dataset defines nine vehicle categories. The class taxonomy and representative examples suggest that some categories with similar shape and scale, such as combi, microbus, and minibus, can be difficult to separate from elevated viewpoints. This observation is reported as a potential source of class-conditional ambiguity rather than as an annotation defect. The analysis code validates that class identifiers stay within the official range, box dimensions are positive, centers are inside the frame, and angles fall within the expected range. The statistical analysis identified 601,934 annotated objects across 54,262 training frames. Among these frames, 3,394 contain no annotated objects, 6,212 contain exactly one object, and 44,656 contain two or more objects. The maximum observed density is 53 annotated objects in one frame. Cross-checks between CSV identifiers and archive image names found one-to-one correspondence in the processed data, with no orphaned annotations or missing image names. These checks are important because the downstream YOLO-OBB conversion and synthetic augmentation both assume exact image-label pairing. The class distribution is strongly long-tailed. Cars account for 481,731 instances, or 80.03\% of all annotated objects, while articulated buses account for only 250 instances. This imbalance is not merely descriptive; it directly affects training and evaluation because the metric averages AP uniformly across classes. A detector that learns the majority class well can still be penalized heavily if minority categories are missed. Table~\ref{tab:dataset_class_distribution} reports the final per-class distribution. The annotation policy is also relevant to interpretation. The dataset documentation and evaluation code treat visible stationary vehicles as a special case because the target annotations correspond to moving vehicles. A single-frame detector cannot infer motion state from appearance alone, so stationary vehicles may appear visually valid while remaining absent from ground truth. This issue is handled methodologically through two separate mechanisms: pseudo-labeling of static slots for train-only augmentation and a homography-compensated temporal filter for evaluation-time prediction suppression. Both mechanisms are described in Section~\ref{sec:material_methods}.
