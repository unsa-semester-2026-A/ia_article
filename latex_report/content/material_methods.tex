\section{Methodology}
\label{sec:material_methods}

\subsection{Methodological Design}
\label{sec:study_design}

The study uses a data-centric ablation design. The workflow first checks the original annotations, assigns complete clips to train or validation, and exports labels in YOLO-OBB format. It then creates a train-only augmentation set by extracting real vehicle masks and placing them in accepted background slots. Training conditions are organized to compare raw frames, classical online augmentation, LaMa-corrected pixels~\cite{Suvorov2022LaMa}, and segmentation-assisted synthetic additions while keeping validation fixed. All final predictions are evaluated with the same Macro AP-rIoU implementation and the same motion filter, so the main experimental variable remains the training data. Training-loop metrics are reported only as diagnostics when they help explain a final-artifact result.

\subsection{Annotation Parsing and Split Construction}
\label{sec:annotation_preprocessing}

The parser first checks \texttt{train.csv} for the expected 54,262 rows and 601,934 object annotations, then extracts a clip identifier from each frame name. The train/validation split is deterministic at clip level, with a 0.8 train ratio and seed 42, to avoid placing neighboring frames from the same temporal sequence in both subsets. Each parametric OBB is converted from center, width, height, and angle into four normalized YOLO-OBB vertices. Coordinates are clipped to the image frame, and one label file is written for every frame; frames marked as \texttt{none} receive empty label files so image-label pairing remains explicit.

\subsection{Static-Slot Pseudo-Labeling}
\label{sec:static_slot_pseudo_labeling}

Safe placement slots are needed so pasted vehicles do not overwrite annotated moving traffic. The pseudo-labeling stage searches for those slots only in train-split clips. It applies zero-shot YOLO-OBB inference, maps DOTA vehicle categories to the task classes, estimates frame-to-frame homographies with ORB and RANSAC, and links detection centroids through time~\cite{Rublee2011ORB,Fischler1981RANSAC,Hartley2004MVG}. A track is treated as static when it spans at least 10 frames, moves less than 8 compensated pixels, and does not correspond to an annotated ground-truth object by centroid proximity. Candidate static OBB slots are stored in JSON and later rejected if they fall outside the resized frame, belong to validation, or overlap a real training OBB.

\subsection{Segmentation-Assisted Copy-Paste Augmentation}
\label{sec:data_augmentation}

The final augmentation stage uses semantic-mask copy-paste rather than relighting as the production mechanism. Earlier IC-Light experiments~\cite{Zhang2025ICLight} were kept as exploratory work, while the final set uses SAM masks and deterministic label writing~\cite{Kirillov2023SAM}. The insertion policy targets minority classes below 2\% of the real annotations, uses seed 42, limits source reuse, and places at most three inserted objects in a synthetic frame. These constraints increase rare-class evidence without allowing a small number of source vehicles to dominate the augmented set.

\subsubsection{Source Track Selection and Mask Extraction}
\label{sec:mask_extraction}

Foreground sources are drawn from real training annotations. Same-class observations within a clip are linked into short tracks using centroid distance, with a 35-pixel association limit. The largest-area observation in each track becomes the crop candidate. Candidates are discarded when the image cannot be read, the OBB lies outside the frame, or the vehicle overlaps another annotated instance. SAM receives a padded axis-aligned box prompt derived from the OBB, while neighboring annotated vehicles are marked as exclusions. A mask is accepted only when it is non-empty, avoids excluded objects, is dominated by one connected component, and remains within 1.25 times the prompt area. The accepted foreground is saved as a tight RGBA crop, so transparency follows the segmentation mask rather than the rectangular crop.

\subsubsection{Object Placement and Composition}
\label{sec:object_composition}

The renderer groups up to three non-overlapping target slots on a single background frame. Backgrounds are read from the LaMa-corrected training directory used by the implementation~\cite{Suvorov2022LaMa}. Each RGBA foreground is projected to the target OBB with a perspective transform from the minimum-area alpha rectangle to the four target corners. The projected object is alpha-composited with a one-pixel feather, and the renderer verifies that pixels outside the semantic support are unchanged. The production renderer does not call IC-Light and does not use full-frame diffusion outputs.

\subsubsection{Label Preservation and Validation}
\label{sec:augmentation_validation}

For each synthetic frame, original background labels are copied first and one YOLO-OBB line is appended for every inserted object. The appended coordinates come from the target OBB corners, are normalized to the 640 by 360 frame, and are clipped to $[0,1]$. The production run stores generated images, labels, insertion records, a JSON summary, a metrics report, and separate ZIP artifacts for the training delta and validation check. Validation rejects any set with missing image-label pairs, synthetic validation files, generated labels without insertion records, out-of-range OBB coordinates, or backgrounds outside the train split. A staging check confirms that the augmented snapshot is complete and that validation data remains unchanged.

\subsection{Training Conditions}
\label{sec:training_conditions}

The training design defines five YOLO26s-OBB F1 conditions, plus a zero-shot reference. Base 1 trains on raw 640 by 360 images with a minimal online augmentation profile. Base 2 keeps the same raw frames but enables stronger classical YOLO augmentations, including Mosaic, MixUp, online copy-paste, random erasing, and HSV perturbation. Improvement A uses LaMa-corrected training pixels with the Base 1 profile. Improvement B adds the frozen SAM copy-paste delta to raw training images, and Improvement C adds the same delta to LaMa-corrected images. Validation images are raw and unchanged for every condition. The evaluation directory also includes Base 0, a zero-shot baseline based on the downloadable \texttt{yolo26s-obb.pt} weights with DOTA vehicle-category mapping to the official Auto and Camion classes.

All F1 runs start from the same YOLO26s-OBB weights and share seed 42, image size 640, AdamW, initial learning rate 0.001, final learning-rate factor 0.01, 40 epochs, patience 5, automatic mixed precision, four workers, and no RAM image cache. Batch size is chosen through a fixed memory-calibration step on two Tesla T4 GPUs, keeping the comparison within the same hardware envelope. \subsection{Motion Filter}
\label{sec:motion_filter}

The motion filter addresses a property of the annotations: the dataset labels moving vehicles, while visible stationary vehicles can still be detected by a model. For each clip, YOLO OBB predictions are converted to official class identifiers, centers, sizes, and angles. Consecutive-frame homographies are estimated from image evidence rather than model outputs, giving every condition the same camera-motion compensation~\cite{Hartley2004MVG}. Detections are greedily associated by class and projected centroid distance, with a 30-pixel maximum distance. Tracks lasting at least 10 frames and moving less than 8 compensated pixels are marked static and removed before scoring. The filter also records diagnostics for total tracks, static tracks, retained tracks, and removed predictions.

\subsection{Evaluation Protocol}
\label{sec:experimental_setup}

Evaluation begins with a low confidence threshold of 0.001 so that ranking-based AP can use the full candidate set. Training labels 0--8 are remapped to official class identifiers 1--9. Malformed predictions, non-finite values, invalid scores, and negative dimensions are handled before scoring. Ground truth is loaded from the SMART CSV for the selected validation frames. After optional motion filtering, predictions are grouped by class and scored with Macro AP-rIoU as defined in Section~\ref{sec:macro_ap_riou}, combining VOC/COCO-style AP with polygon overlap for oriented boxes~\cite{Everingham2015PASCAL,Lin2014COCO,Ding2022DOTA}. Each final evaluator package stores predictions, homographies, detailed metrics, Macro AP-rIoU, AP at rIoU 0.50, and AP at rIoU 0.80. Training-only outputs, such as Ultralytics validation curves, are treated as convergence diagnostics and are not merged with the final Macro AP-rIoU table.
