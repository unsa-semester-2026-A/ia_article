\subsection{Study Design}
\label{sec:study_design}

The implemented workflow follows a data-centric experimental design. First, the raw competition annotations are parsed, checked, split at clip level, and converted to YOLO-OBB labels. Second, a train-only augmentation set is produced by extracting real vehicle masks and inserting them into safe background slots. Third, YOLO26s-OBB training conditions are assembled so that raw data, classical online augmentation, LaMa-corrected training pixels, and segmentation-assisted synthetic deltas can be compared without changing the validation split. Finally, predictions are evaluated with the same Macro AP-rIoU metric and a shared motion filter. This section describes the implemented pipeline and the evaluation protocol.

\subsection{Annotation Parsing and Split Construction}
\label{sec:annotation_preprocessing}

The preprocessing module reads \texttt{train.csv}, validates the expected 54,262 rows and 601,934 object annotations, and derives each clip identifier from the frame name. It then performs a deterministic train/validation split over unique clips using a train ratio of 0.8 and seed 42. This design prevents frames from the same temporal sequence from appearing in both train and validation. For each row, the parser converts every parametric OBB into four normalized YOLO-OBB vertices. The conversion uses the OBB center, width, height, and angle in degrees, applies the corresponding rotation matrix, clips coordinates to the image frame, and writes one label file per frame. Empty frames are represented by empty label files rather than missing files, preserving one-to-one image-label correspondence.

\subsection{Static-Slot Pseudo-Labeling}
\label{sec:static_slot_pseudo_labeling}

The augmentation pipeline requires target locations where additional vehicles can be inserted without overwriting annotated moving vehicles. These locations are obtained from the pseudo-labeling module, which runs zero-shot YOLO-OBB inference over train-split clips, maps DOTA vehicle categories dynamically, estimates frame-to-frame homographies with ORB features and RANSAC, and tracks detection centroids over time. A trajectory is considered static when it lasts at least 10 frames, has a compensated displacement below 8 pixels, and does not match an annotated ground-truth vehicle by centroid proximity. The static-vehicle JSON file stores candidate OBB slots for stationary, unannotated vehicles. During augmentation preparation, those slots are converted from the pseudo-label source resolution to the 640 by 360 training frame and are rejected if they fall outside the frame, belong to a validation clip, or overlap any real training OBB.

\subsection{Segmentation-Assisted Copy-Paste Augmentation}
\label{sec:data_augmentation}

The final augmentation method is a semantic-mask copy-paste pipeline. It replaces the earlier exploration centered on IC-Light with a deterministic train-only set based on SAM masks and explicit label preservation. The selected policy uses $\tau=0.02$, a reuse cap of 10, a full quota budget, seed 42, and at most three inserted objects per synthetic image. The quota rule adds instances only for classes whose real frequency is below the 2\% threshold, and it caps each class by the number of real instances, available source tracks, and the reuse limit. This prevents unlimited replication of a small set of rare objects.

\subsubsection{Source Track Selection and Mask Extraction}
\label{sec:mask_extraction}

Source vehicles are selected from real train labels. The pipeline links same-class observations within a clip into short tracks by matching centroids across nearby frames; a new track is created when no recent same-class observation lies within the 35-pixel association distance. For each track, the largest-area OBB observation is chosen as the crop source. Sources are rejected if the image is unreadable, the OBB is outside the frame, or the object overlaps another annotated vehicle. For production, a SAM masker is mandatory. The OBB is converted into a padded axis-aligned box prompt, neighboring annotated vehicles are painted into an exclusion mask, and SAM candidates are ranked before deterministic geometry checks are applied. A candidate mask is accepted only if it is non-empty, avoids excluded objects, is dominated by a single connected component, and does not exceed 1.25 times the prompt area. The accepted mask is written as a tight RGBA crop, so transparent pixels are based on semantic segmentation rather than on the rectangular OBB footprint.

\subsubsection{Object Placement and Composition}
\label{sec:object_composition}

Rendering uses grouped jobs that place up to three non-overlapping target slots into one background frame. The background image is read from the LaMa-corrected training directory used by the implementation. Each RGBA crop is warped to the target OBB through a perspective transform from the crop's minimum-area alpha rectangle to the four target OBB corners. The warped foreground is then alpha-composited over the background using a one-pixel feathered mask. A validation check confirms that pixels outside the feathered semantic support remain identical to the previous background. The production renderer excludes IC-Light relighting and does not admit full-frame diffusion outputs.

\subsubsection{Label Preservation and Validation}
\label{sec:augmentation_validation}

For every synthetic image, the renderer copies the original background label lines and appends one YOLO-OBB line for each inserted object using the target OBB corners. The writer normalizes all eight coordinates to the 640 by 360 frame and clips them to the closed interval $[0,1]$. The production command stages the generated images and labels under train directories, records one entry per inserted object, stores a JSON summary, exports a metrics report, and creates separate training-delta and validation ZIPs. The validation routine refuses generated sets with missing image-label pairs, unexpected validation outputs, generated labels without corresponding insertion records, out-of-range OBB coordinates, or backgrounds outside train clips. A separate staging script checks that the generated set is copied into a complete Kaggle dataset snapshot without modifying validation data.

\subsection{Training Conditions}
\label{sec:training_conditions}

The final training runner defines five YOLO26s-OBB conditions in the F1 family. Base 1 uses raw 640 by 360 training images with a minimal online augmentation profile. Base 2 uses the same raw frames but enables classical YOLO augmentation, including Mosaic, MixUp, online copy-paste, random erasing, and stronger HSV perturbations. Improvement A uses LaMa-corrected training images while keeping the Base 1 augmentation profile. Improvement B uses raw training images plus the frozen SAM copy-paste synthetic delta, and Improvement C uses LaMa-corrected training images plus the exact same synthetic delta. In all conditions, validation images remain raw and unchanged. The final evaluation directory also includes Base 0 as an evaluation-only zero-shot baseline that uses the downloadable \texttt{yolo26s-obb.pt} weights and maps DOTA vehicle categories to the official Auto and Camion classes.

All F1 conditions start from the same YOLO26s-OBB weights. They share seed 42, image size 640, AdamW optimizer, initial learning rate 0.001, final learning-rate factor 0.01, 40-epoch budget, patience 5, automatic mixed precision, four workers, and no RAM image cache. The default global DDP batch is 96 on two Tesla T4 GPUs. The Base 2 runner includes a memory calibration ladder over global batches 96, 48, 32, and 24; the recorded production run selected batch 48 to avoid a TaskAlignedAssigner CPU fallback while preserving the intended effective update through accumulation. \subsection{Motion Filter}
\label{sec:motion_filter}

The evaluation pipeline uses homographies to filter static detections because the dataset annotations target moving vehicles. For each clip, YOLO predictions are converted from Ultralytics OBB output to official class identifiers, pixel centers, dimensions, and degree angles. Homographies are estimated from consecutive frames independently of model predictions, using image evidence only, so that every experimental condition receives the same camera-motion compensation. Detections are associated into tracks greedily by class and projected centroid distance, with a maximum association distance of 30 pixels. Tracks lasting at least 10 frames and moving less than 8 compensated pixels are classified as static, and their detections are removed before metric computation. The filter returns both filtered predictions and diagnostics listing total tracks, static track identifiers, retained track identifiers, and removed prediction counts.

\subsection{Evaluation Protocol}
\label{sec:experimental_setup}

The evaluation code uses a confidence threshold of 0.001 to collect model candidates before metric ranking. It converts training class identifiers 0 through 8 into official class identifiers 1 through 9, discards malformed or non-finite predictions, canonicalizes negative dimensions when encountered, and rejects scores outside $[0,1]$. Ground-truth annotations are loaded from the SMART CSV for the selected validation frames. After optional motion filtering, predictions are grouped by class and evaluated with Macro AP-rIoU as defined in Section~\ref{sec:macro_ap_riou}. For each condition, the evaluation protocol records predictions, homographies, metric details, and summary values such as Macro AP-rIoU, macro AP at rIoU 0.50, and macro AP at rIoU 0.80.

\subsection{Data Access Statement}
\label{sec:data_access}

The competition data are available through the Kaggle SMART Challenge page after accepting the competition and platform terms~\cite{MTC2026SmartChallenge}. The source code contains scripts for parsing, preprocessing, training, augmentation, and evaluation, but it does not redistribute \texttt{train.zip}, \texttt{test.zip}, \texttt{train.csv}, or \texttt{sample\_submission.csv}. Private collaborative mirrors are not primary public dataset sources.
