\section{Background}
\label{sec:theoretical_background}

\subsection{Traffic Video Detection}
\label{sec:traffic_video_detection}

Visual traffic monitoring supports tasks such as flow estimation, vehicle classification, and incident analysis. Cameras are useful in this context because they provide dense spatial evidence from infrastructure that many cities already operate. The challenge is that urban footage is not visually stable: lighting, congestion, occlusion, camera placement, and fleet composition can change the appearance of the same class across locations~\cite{Zhou2025TrafficSurveillanceSurvey,Azfar2024ComplexTrafficReview}. Object-detection surveys also emphasize that performance depends on the training data distribution, not only on the network architecture~\cite{Zou2023ObjectDetectionSurvey}. For this reason, data preparation, annotation geometry, and evaluation design are treated here as part of the detection problem itself.

\subsection{Oriented Bounding Boxes}
\label{sec:oriented_bounding_boxes}

Many detectors represent object location with horizontal bounding boxes. That representation is compact, but it is poorly aligned with vehicles seen at arbitrary headings because it encloses background and can blur the separation between nearby instances. OBBs add orientation, either as center-size-angle parameters or as four rotated vertices, so the annotation follows the object footprint more closely~\cite{Wang2025OBBSurvey,Zand2022OBB}. For elevated traffic views, this geometric detail is relevant because orientation errors can affect downstream measurements and interpretation~\cite{Ahmed2025}.

\subsection{Rotated Intersection over Union}
\label{sec:riou_metric}

Rotated Intersection over Union (rIoU) compares two oriented boxes as polygons. It differs from horizontal IoU because the overlap is computed on the rotated quadrilaterals, making the score sensitive to heading, scale, and center error at the same time. This follows the logic of oriented-detection benchmarks such as DOTA, where polygon overlap is used while the overall detection protocol remains related to the PASCAL VOC tradition~\cite{Ding2022DOTA,Everingham2015PASCAL}. For a predicted box $B_p$ and a ground-truth box $B_g$, rIoU is defined as
\begin{equation}
  \operatorname{rIoU}(B_p,B_g) =
  \frac{\left|P(B_p)\cap P(B_g)\right|}
       {\left|P(B_p)\cup P(B_g)\right|},
  \label{eq:riou}
\end{equation}
where $P(\cdot)$ is the polygon induced by an OBB and $|\cdot|$ is polygon area. The value is 1 for identical polygons and 0 when there is no overlap. In traffic scenes, this strictness is useful because a diagonal vehicle can be roughly centered while still having an incorrect footprint or orientation.

\subsection{Macro AP-rIoU}
\label{sec:macro_ap_riou}

Macro AP-rIoU combines class-balanced AP with rotated overlap. The protocol uses nine vehicle classes and seven rIoU thresholds, $\mathcal{T}=\{0.50,0.55,\ldots,0.80\}$. As in standard object-detection evaluation, detections are ordered by confidence and summarized through Average Precision (AP) on the precision--recall curve~\cite{Everingham2015PASCAL,Lin2014COCO}. For each class and threshold, a prediction can match only an unused ground-truth box from the same frame and class. The final score is
\begin{equation}
\begin{aligned}
  \operatorname{MacroAP}_{rIoU}
  = \frac{1}{9}\sum_{c=1}^{9}
    \frac{1}{|\mathcal{T}|}\sum_{\tau\in\mathcal{T}}
    \operatorname{AP}_{c,\tau}.
\end{aligned}
\label{eq:macro_ap_riou}
\end{equation}
The macro average is intentionally class-balanced. In a long-tailed dataset, high AP for cars should not hide failure on rare vehicle types. The metric therefore matches the motivation for minority-class augmentation while retaining the geometric strictness of rIoU.

\subsection{Small Objects and Class Imbalance}
\label{sec:small_objects_imbalance}

Elevated cameras often capture vehicles that are small in the image or partially hidden by surrounding traffic. Small-object surveys relate this difficulty to downsampling, weak feature support, and cluttered context~\cite{Cheng2023SmallObjectSurvey,Nikouei2025SmallObjectSurvey}. Class imbalance adds a second pressure: frequent classes dominate optimization, while rare classes provide fewer examples and less appearance variation. Studies on motorcycle detection and oriented aerial vehicle detection indicate that vulnerable or minority vehicle classes often need targeted modeling or balancing strategies~\cite{Espinosa2020,Mo2020}. These observations support both the class-aware metric and the data-level augmentation strategy used in this study.

\subsection{Segmentation-Assisted Synthetic Augmentation}
\label{sec:segmentation_assisted_augmentation_background}

Synthetic data is useful for detection only when it adds variation without damaging the labels. Prior work reports benefits from combining real and artificial images, while also warning that domain gaps and visual artifacts can reduce the value of generated samples~\cite{Weber2021ArtificialImagesVehicleDetection,Mumuni2024}. Recent methods therefore use segmentation masks or region-level controls to protect object identity and spatial consistency~\cite{Rahat2024,Benkedadra2024,ZhuH2025}. The workflow in this paper follows that conservative direction: the final training data uses mask-guided copy-paste rather than full-frame image generation.
